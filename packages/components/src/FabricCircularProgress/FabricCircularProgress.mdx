# FabricCircularProgress

Loading spinner for asynchronous work — button submit states, layout skeleton screens, tree-row fetches, and full-page load overlays. Extends MUI `CircularProgress` verbatim; the one change is that `size` defaults to `24` (MUI's default is `40`), which suits buttons, rows and dense layouts.

**Use it for:**
- Submit-button spinners inside disabled `<Button>` while saving
- Layout-level "loading…" overlays before initial data arrives
- Inline tree-row / table-cell activity indicators
- Determinate progress with a percentage label overlay

**Quick links:** [Source](https://github.com/ahmedBilal5/fabric/blob/main/packages/components/src/FabricCircularProgress/index.tsx) · [Material Design guidance](https://m2.material.io/components/progress-indicators)

## Sizes

`size` accepts both `number` (px) and `string` (any CSS length — `"1.5rem"`, `"32px"`, `"2em"`). Default is `24`.

<Canvas of={CircularProgressStories.AllSizes} />
<Canvas of={CircularProgressStories.StringSize} />

Common sizing conventions in the codebase:

| Context | Size |
|---|---:|
| Inline inside a table / tree row | `14–20` |
| Inside a submit button | `16` |
| Layout skeleton loading | `24` (default) |
| Page-level overlay | `40` |
| Determinate with percentage label | `56` |

## Indeterminate vs. determinate

`variant="indeterminate"` (default) spins continuously and is used when the total work is unknown. `variant="determinate"` fills the ring from `0` to `value` (`0–100`) and is used when progress is measurable.

## Accessibility

MUI's `CircularProgress` renders as `role="progressbar"` with `aria-valuemin={0}` and `aria-valuemax={100}` (plus `aria-valuenow={value}` in determinate mode). Screen readers announce it correctly out of the box.

For indeterminate spinners inside a labeled region (a section, a card, a dialog), no additional `aria-label` is needed — the surrounding context supplies the "what is loading" narration. For bare page-level spinners, add an `aria-label="Loading…"` explicitly.

```tsx
<FabricCircularProgress aria-label="Loading products" />
```

## Anti-patterns

Do **not** use `FabricCircularProgress` for:

- **Buttons that should stay clickable while loading.** Use MUI `<LoadingButton>` (the button itself owns the spinner slot).
- **Long-running background work** where the user has moved on. Fire a `FabricSnackbar` with an action instead — a spinner someone can't see is invisible progress.
- **Skeleton loading of *content*.** Use MUI `<Skeleton>` — it conveys shape and hierarchy while loading, not just "something is happening".
