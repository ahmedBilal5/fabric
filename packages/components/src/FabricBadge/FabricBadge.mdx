# FabricBadge

Badge generates a small badge to the top-right of its child(ren). `FabricBadge` wraps MUI `Badge` with the full MUI surface. You get the entire MUI Badge API (variants, colors, anchors, max cap, dot mode) as-is.

**Use it in:**
- Notification counts on icon buttons (mail, alerts, chat)
- Presence dots on avatars (`variant="dot"` + `overlap="circular"`)
- "NEW" / "!" indicators on menu items and tiles
- Status pills over profile pictures

**Do not use for:** standalone tags or labels (use [FabricChip](?path=/docs/components-fabricchip--overview)) · progress indicators (use [FabricProgressChip](?path=/docs/components-fabricprogresschip--overview) or [FabricCircularProgress](?path=/docs/components-fabriccircularprogress--overview)) · alerts / banners (use [FabricAlert](?path=/docs/components-fabricalert--overview)).

**Quick links:** [Source](https://github.com/ahmedBilal5/fabric/blob/main/packages/components/src/FabricBadge/index.tsx) · [MUI Badge](https://mui.com/material-ui/react-badge/) · [WAI-ARIA status pattern](https://www.w3.org/WAI/ARIA/apg/patterns/status/)

## Basic usage

Wrap any element with `<FabricBadge>` and pass `badgeContent`. The badge anchors to the top-right of the child by default.

## Accessibility

- `<Badge>` is decorative — the underlying anchor element must carry an accessible label that includes the badge context. Example: `<IconButton aria-label="4 new mails">`.
- MUI does not render an `aria-live` region for badge updates. If dynamic badge changes must be announced to screen readers, wrap the badge in an element with `role="status"` and `aria-live="polite"`.
- Dot variant carries no semantic value on its own — always pair with a label on the anchor.
