# FabricTooltip

Informative hover / focus text for compact controls. Use it on icon buttons, truncated labels and abbreviations. Extends MUI `Tooltip`, accepts any `ReactNode` as `title`, and applies Fabric's tooltip look (typography, padding, radius, shadow) from `@fabric-kit/design-tokens`. The default `dark` variant is navy; `variant="light"` is white.

**Use it for:**
- Icon-button labels (Delete, Archive, Share)
- Truncated text ("... expand")
- Abbreviation / jargon explanations ("MDM", "PIM")
- Keyboard shortcut hints on toolbar buttons

**Do not use for:** critical information the user must see (make it visible) · long-form content (use a Popover) · touch-only devices (tooltips don't fire on touch by default).

**Quick links:** [Source](https://github.com/ahmedBilal5/fabric/blob/main/packages/components/src/FabricTooltip/index.tsx) · [WAI-ARIA tooltip pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/) · [Material Design guidance](https://m2.material.io/components/tooltips)

## Variants

`variant="dark"` (default, navy) and `variant="light"` (white).

Both follow the theme mode:

| Variant | Light mode | Dark mode |
|---|---|---|
| `dark` | `brand.navy` fill, `text.inverse` text | `dark.brand.navy` fill, `dark.text.inverse` text (lighter, so it stands out) |
| `light` | `surface.primary` fill, `text.medium` text | `dark.surface.primary` fill, `dark.text.medium` text |

## Limitations

### Custom child elements must forward refs

Tooltip attaches DOM event listeners to its child. Custom React components must forward refs to the underlying DOM node — otherwise the tooltip won't fire. Wrap non-forwardRef components in a `<span>`.

### Disabled buttons need a `<span>` wrapper

Native `<button disabled>` doesn't fire pointer events. Wrap it in a `<span>` (Fabric [FabricButton](?path=/docs/components-fabricbutton--overview) already does this internally when the `tooltip` prop is set).

### `describeChild` matters for accessibility

When the tooltip's content matches the anchor's visible label, the tooltip acts as description (not a duplicate label). Pass `describeChild` — screen readers announce the anchor's own label plus the tooltip as extra info. When the anchor has no visible text (icon-only buttons), leave `describeChild` off so the tooltip becomes the accessible name.

### Touch triggers require long-press

Tooltips fire on hover/focus; on touch devices they require a 700ms long-press (`enterTouchDelay`). For crucial info on touch-primary UIs, prefer inline labels or `Popover`.

### `componentsProps` (v5) → `slotProps` (v9)

MUI renamed the API. Use `slotProps={{ tooltip: { sx }, arrow: { sx } }}` instead of `componentsProps`.

### `PopperProps` (v5) → `slotProps.popper` (v9)

Pass popper options through `slotProps.popper`.
