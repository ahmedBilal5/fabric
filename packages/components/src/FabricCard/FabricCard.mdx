# FabricCard

Cards contain content and actions about a single subject. `FabricCard` is a thin wrapper over MUI `Card`. You compose the inside with Fabric card parts and MUI `CardHeader`, `CardMedia`, `CardContent` and `CardActions`, so one shell covers every layout.

**Visual defaults:** `borderRadius: 8px` (`radii.lg`), no border, and a soft resting shadow (`shadows.sm`). Interactive cards lift to `shadows.md` on hover. Consumers who want more elevation opt in with `raised` or `elevation={n}`, and any `sx` override wins on the keys it spells out.

**Parts:** `FabricCard` (the shell) · `FabricCardHeader` (icon, title, description, action) · `FabricCardRows` (label / value rows) · MUI `CardContent`, `CardActions` and `CardMedia` for everything else. Every card below (app, tag, metric, list item) is the same shell with different parts inside. The header styling lives in `FabricCardHeader`; raw MUI card parts are not restyled.

**More layouts:** see **Components/FabricCard/Recipes** for a create card, an app launcher tile, a collection card and a record card.

**Use it in:**
- Grid views of projects, templates or datasets
- App and integration tiles
- Dashboard metrics
- Any listing where each item needs its own visual container

**Do not use for:** page-level containers (use plain `Box` / `Paper`) · dialog surfaces (use [FabricDialog](?path=/docs/components-fabricdialog--overview)) · form field grouping (use `Box` with a border).

**Quick links:** [Source](https://github.com/ahmedBilal5/fabric/blob/main/packages/components/src/FabricCard/index.tsx) · [MUI Card](https://mui.com/material-ui/react-card/) · [MUI Paper](https://mui.com/material-ui/react-paper/) (Card extends Paper)

## List item card

A list item with a drag handle, an icon, a title and compact rows. Same shell as every other card; the differences are props. `tint` sets the background (`neutral`, `blue`, `teal` or `lime`, e.g. one per data source) and `FabricCardRows size="compact"` gives the 12px rows.

The tints reuse the existing status surface tokens (`surface.queued`, `surface.running`, `surface.tertiary`, `surface.success`), so they share colours with the status chips. A tinted card keeps its tint on hover and press and only changes the shadow. The drag handle is visual only; connect your own drag and drop.

## Accessibility

- MUI Card is a plain `<div>` — it carries no ARIA role by itself. Add semantic wrappers (e.g. `<article>`) via `component='article'` when the card represents a discrete piece of content.
- A card with `onClick` (or `interactive`) gets `role="button"`, `tabIndex={0}`, a visible focus ring, and Enter / Space activation. Keys pressed on controls inside the card do not trigger the card. If the card contains its own buttons or links, prefer making only the title a link and leave the card non-interactive.
- `selected` on an interactive card is announced through `aria-pressed`.
- `CardHeader.action` is the correct slot for a card-level menu button — always give it an accessible label.
- `FabricCardRows` renders a `<dl>` so label / value pairs are exposed as a description list.

## Responsive behavior

Cards fill their container. For a fixed width such as 320px, use `sx={{ width: 320 }}` or the parent grid. Text wraps inside the 16px padding rather than overflowing.
