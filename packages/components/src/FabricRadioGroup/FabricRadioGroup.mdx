# FabricRadioGroup

Data-driven radio group with a first-class `options` API. Wraps MUI's `<FormControl>` + `<FormLabel>` + `<RadioGroup>` + `<FormHelperText>` and generates a unique `name` per instance so multiple groups on one page don't interfere. Semantic `variant="warning"` for high-attention selections.

**Use it for:**
- Payment method / Shipping option / Priority level pickers
- Yes/No/Maybe forms (single mutually-exclusive choice)
- Sort direction / Layout mode / Theme mode selectors
- Any small enum picker where the user must see all options

**Do not use for:** ≥7 options (use [FabricSelect](?path=/docs/components-fabricselect--overview)) · multi-select (use [FabricCheckboxGroup](?path=/docs/components-fabriccheckboxgroup--overview)).

**Quick links:** [Source](https://github.com/ahmedBilal5/fabric/blob/main/packages/components/src/FabricRadioGroup/index.tsx) · [WAI-ARIA radio pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/)

## Limitations

### Options are data, children are not accepted

Unlike [FabricCheckboxGroup](?path=/docs/components-fabriccheckboxgroup--overview), `FabricRadioGroup` requires the `options` array — passing `children` won't render radios. This is intentional: the data-driven API guarantees every radio shares the group's `name`.

### Custom control per option

If a specific option needs a custom control (e.g. a colored radio), pass `controlComponent` — replaces the underlying radio input for every option. Per-option custom controls aren't supported; use standalone [FabricRadio](?path=/docs/components-fabricradio--overview) instances inside a custom layout for that case.

### `size` set globally on the group

Passing `size` on the group applies to every option. To vary sizes per option, use standalone `FabricRadio` instances instead.
