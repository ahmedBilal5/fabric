# FabricSelect

Dropdown picker for one-from-many selections when there are too many options for radios. Extends MUI `Select` with a data-driven `options` API, first-class `error` / `helperText`, and typed `renderValue` that searches both the `options` array and any `<MenuItem>` children.

**Use it for:**
- ≥5 mutually exclusive options ("Assign to..." with all workspace members, "Country" pickers)
- Filter-bar dropdowns
- Inline table-cell editors
- Form fields where the answer set is finite but too long for radios

**Do not use for:** ≤4 options where every choice matters (use [FabricRadioGroup](?path=/docs/components-fabricradiogroup--overview)) · free-text with suggestions (use MUI `Autocomplete`) · multi-select (compose with MUI's `Select multiple` pattern).

**Quick links:** [Source](https://github.com/ahmedBilal5/fabric/blob/main/packages/components/src/FabricSelect/index.tsx) · [WAI-ARIA combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/) · [Material Design guidance](https://m2.material.io/components/menus#exposed-dropdown-menu)

## Limitations

### `options` vs `children` — both are supported

Unlike [FabricRadioGroup](?path=/docs/components-fabricradiogroup--overview), FabricSelect accepts either. If you pass both, children render after the `options` items.

### `renderValue` typing

`renderValue` is typed as `(selected: string) => ReactNode`. Multi-select generic (`Select<T[]>`) isn't currently exposed — use raw MUI `Select` for multi-select scenarios.

### `containerSx` vs `sx`

`containerSx` targets the outer `<FormControl>` wrapper (`minWidth`, layout); `sx` targets the inner `<Select>`. Keeping them separate means `minWidth` and layout styles land where you expect.

### No multi-select shortcut

Set `multiple` via `SelectProps` and manage the value as `string[]` — Fabric doesn't add a helper because the multi-select UX (chips? checkbox items? Bulk actions?) is highly context-specific.
