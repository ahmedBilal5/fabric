# FabricCheckbox

Checkboxes let users select one or more items from a set. Use it for settings, filters and multi-select rows. Extends MUI `Checkbox`, defaults `color="primary"`, and adds a first-class `label` slot so labeled checkboxes don't need a separate `<FormControlLabel>` wrapper.

**Use it for:**
- Boolean settings (Enable dark mode, Reduced motion)
- Multi-select filters and table rows
- Terms-of-service agreement rows
- Bulk-action headers with the indeterminate state

**Quick links:** [Source](https://github.com/ahmedBilal5/fabric/blob/main/packages/components/src/FabricCheckbox/index.tsx) · [WAI-ARIA checkbox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/) · [Material Design guidance](https://m2.material.io/components/selection-controls#checkboxes)

## Limitations

### Indeterminate is display-only

`indeterminate={true}` visually shows the mixed state but `checked` still submits as boolean. Persist your "some / all / none" state separately from `checked`.

### `onChange` vs `onCheckedChange` fire order

When both are supplied, `onChange(event, checked)` fires FIRST, then `onCheckedChange(checked)`. Consumers that call `event.preventDefault()` in `onChange` will still see the boolean handler fire — this is intentional so uncontrolled analytics can piggyback.

### `label` types

`label` is typed as `ReactNode` — but MUI's `<FormControlLabel>` `label` prop is `ReactNode`, so this is a widening. Passing complex nodes (icons + text) works; passing `null` renders the checkbox with an empty label wrapper. Prefer omitting `label` entirely for icon-only cells.
