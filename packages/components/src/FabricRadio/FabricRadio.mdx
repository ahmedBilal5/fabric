# FabricRadio

Single radio input for mutually exclusive selections. Use it for "pick one" choices such as payment method, priority or sort direction, inside a [FabricRadioGroup](?path=/docs/components-fabricradiogroup--overview). Extends MUI `Radio` and adds a first-class `label` slot.

**Use it for:**
- Mutually exclusive options where the user needs to see all choices at once
- Prefer over [FabricSelect](?path=/docs/components-fabricselect--overview) when there are ≤5 options and screen space allows

**Do not use for:** on/off toggles (use [FabricSwitch](?path=/docs/components-fabricswitch--overview)) · multi-select (use [FabricCheckbox](?path=/docs/components-fabriccheckbox--overview)) · long option lists (use [FabricSelect](?path=/docs/components-fabricselect--overview)).

**Quick links:** [Source](https://github.com/ahmedBilal5/fabric/blob/main/packages/components/src/FabricRadio/index.tsx) · [WAI-ARIA radio pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) · [Material Design guidance](https://m2.material.io/components/selection-controls#radio-buttons)

## Limitations

### Standalone radios rarely make sense

A radio without a group is semantically odd — it can't be deselected once checked. Use `FabricRadio` standalone only inside custom form rows where the parent handles grouping via `name`. Prefer [FabricRadioGroup](?path=/docs/components-fabricradiogroup--overview) for anything user-facing.

### Same `name` requirement

Multiple radios must share a `name` to behave as a group. [FabricRadioGroup](?path=/docs/components-fabricradiogroup--overview) auto-generates a unique `name` via `useId()`; if using standalone radios, you must pass matching `name` values yourself or radios from different groups will interfere.

### Keyboard navigation belongs to the group

Arrow-key navigation between radios (WAI-ARIA requirement) is provided by `<RadioGroup>`, not by individual radios. Standalone radios have no roving tab-index.
