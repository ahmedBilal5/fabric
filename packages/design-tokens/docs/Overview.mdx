## What Are Design Tokens?

Design tokens are the **atomic visual values** that define how a product looks and feels.
Rather than scattering raw hex codes, pixel values, and font stacks throughout a codebase,
tokens give those values **semantic names** that communicate *intent* rather than implementation.

A token is the smallest piece of a design system's visual language: a named constant that
represents a specific design decision. When the design picks Fabric's clay for interactive
elements, that decision becomes the token `action.primary`. When the spacing between
sections is 24px, that decision becomes `spacing.xl`.

### Why tokens instead of raw values?

## Naming Convention

Tokens follow a **category → role** pattern that reads like natural language:

```
category.role
```

Examples:
- `text.primary` — main foreground color
- `surface.tertiary` — third-level background
- `action.primaryHover` — button hover state
- `spacing.xl` — large spacing step (24px)
- `shadows.md` — medium elevation

### Why semantic names?

| Approach | Code | Problem |
|----------|------|---------|
| Raw value | `color: '#B23E2A'` | Meaningless: what is this red for? |
| Descriptive | `color: colors.blue600` | Still abstract — when do I use 600 vs 500? |
| **Semantic** | `color: action.primary` | Clear intent — this is an interactive primary element |

Semantic naming answers the question *"what role does this value play?"* rather than
*"what does this value look like?"*. This makes code self-documenting and makes it
possible to swap visual values (e.g., rebrand, dark mode) without changing any consumer code.

## Usage

### Install

```bash
npm install @fabric-kit/design-tokens
```

### Import tokens directly

```tsx
import { brand, text, spacing, shadows } from '@fabric-kit/design-tokens';

// Use in inline styles, CSS-in-JS, or anywhere that accepts values
const header = {
  color: text.heading,
  padding: spacing.lg,
  boxShadow: shadows.header,
  backgroundColor: brand.primary,
};
```

### Through the theme (recommended)

In most cases, you don't import tokens directly — they flow through `@fabric-kit/theme`:

```tsx
import { FabricButton } from '@fabric-kit/components';

// The button already uses action.primary, text.inverse, spacing.md internally.
// You never need to specify colors — the design system handles it.
<FabricButton variant="contained">Save</FabricButton>
```

When you need a token value in custom styling, use the MUI `sx` prop which references the theme (which references the tokens):

```tsx
<Box sx={{ color: 'text.secondary', p: 2, borderRadius: 1 }} />
```

### TypeScript support

Every token object is exported `as const` with a corresponding type.
This gives you full autocomplete and compile-time validation:

```tsx
import { spacing, type Spacing } from '@fabric-kit/design-tokens';

function getSpacing(key: keyof Spacing): number {
  return spacing[key]; // Only valid keys accepted
}
```

## Design Decisions

### One direction of flow

Changes flow one way: tokens → theme → components. A component never defines a color or
size that the tokens or theme don't already name.

### Flat objects over deeply nested trees

Tokens are organized as flat objects (`text.primary`, `spacing.xl`) rather than deeply
nested structures (`tokens.color.text.primary.value`). This keeps imports simple,
autocomplete fast, and bundle size minimal.

### Dark mode as a parallel token set

Rather than runtime CSS variable swapping at the token level, `@fabric-kit/design-tokens`
exports a `dark` object with the same shape as the light tokens. The `@fabric-kit/theme`
package handles the actual mode switching using MUI's CSS variable strategy —
tokens stay pure data.

### Constrained scales

Spacing, font size, radii, and z-index use **named steps** (`xs`, `sm`, `md`, `lg`, `xl`)
rather than arbitrary numbers. This prevents "spacing drift" where developers invent
one-off values (13px, 17px, 22px) that slowly erode visual rhythm.

## Adding or Modifying Tokens

1. **Edit the corresponding file** in `packages/design-tokens/src/` (e.g., `colors.ts`, `spacing.ts`).
2. **Export from `index.ts`** if adding a new category.
3. **Run the build** — `pnpm turbo build --filter=@fabric-kit/design-tokens`.
4. **Update downstream** — if the token feeds into `@fabric-kit/theme`, update the mapping there.
